**MCP** (Model Context Protocol) is how an AI app talks to *other programs* in a standard way: list what they can do, then call those capabilities with JSON.

## Read this in order

Short jargon note — read top to bottom:

1. **The cast** — Terms and mental model before the examples.
2. **A tiny tool call** — Runnable code or data to copy.

## The cast

**Plain English:** The cast — definition, example, and where you will see it.

```txt
you → host (Cursor, Claude, …) → MCP client → MCP server → files / APIs / DB
```

| Piece | Role |
| --- | --- |
| <Term id="mcp-host">Host</Term> | The app you sit in. Owns the model and approvals. |
| <Term id="mcp-client">Client</Term> | One connection from the host to one server. |
| <Term id="mcp-server">Server</Term> | Exposes tools, resources, prompts. Does **not** run the LLM. |
| <Term id="mcp-tool">Tool</Term> | A function the model can call (`search`, `write_file`). |
| <Term id="mcp-resource">Resource</Term> | Read-only blob with a URI. |
| <Term id="mcp-prompt">Prompt</Term> | Named message template (slash command). |

It is not a model. It is not a replacement for REST in your product UI. It is the USB-C of **agent context**: one protocol, many servers.

## A tiny tool call

**Plain English:** A tiny tool call — definition, example, and where you will see it.

The host asks the server what exists (`tools/list`), then the model picks a name, and the host sends <Term id="json-rpc">JSON-RPC</Term>:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "search_docs",
    "arguments": { "query": "lockfile" }
  }
}
```

The server returns text (or an error). The host stuffs that into the chat. You never paste the docs by hand.
