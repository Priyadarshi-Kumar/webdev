A **hook** is a function whose name starts with `use`. You call it at the **top level** of a function component (or another hook). React matches calls by **order**, so do not put them in `if` or loops.

## A minimal example

**Plain English:** A minimal example — definition, example, and where you will see it.

```tsx
import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

`useState` is a hook. Each render, React returns the current `count` and a setter. The setter queues an update; React renders again with the new value.

## The rules (why order matters)

**Plain English:** The rules (why order matters) — definition, example, and where you will see it.

1. Top level only — not inside `if`, loops, or nested functions.
2. React functions only (components and <Term id="custom-hook">custom hooks</Term>).
3. Same number of calls every render.

```tsx
function Broken({ premium }: { premium: boolean }) {
  if (premium) {
    const [bonus, setBonus] = useState(0); // shifts every other hook down
  }
  const [name, setName] = useState("");
  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}
```

React stores hook state in a list. Skip a call, and `name` might read `bonus`’s slot. The linter (`eslint-plugin-react-hooks`) catches this.

## Built-in vs yours

**Plain English:** Built-in vs yours — definition, example, and where you will see it.

Built-ins you will meet: `useState`, `useEffect`, `useContext` / `use`, `useRef`, `useMemo`, `useCallback`, `useId`, `useSyncExternalStore`. A function you write that calls these is a custom hook — same rules, reusable logic.
