A **hard link** is a second directory entry that points at the **same inode** (same bytes). Delete one name, the bytes stay until the last name is gone.

## Tiny demo

```bash
echo hello > a.txt
ln a.txt b.txt          # hard link (not a shortcut)
echo world >> a.txt
cat b.txt               # hello\nworld — same file
ls -i a.txt b.txt       # same inode number
```

A **symlink** (`ln -s`) is different: it stores a *path* to another name. If the target moves, the symlink breaks. Hard links do not care about the other name.

```bash
ln -s a.txt link.txt
mv a.txt gone.txt
cat link.txt            # broken — still points at a.txt
```

## Why pnpm cares

pnpm hard-links (or copy-on-Windows fallbacks) from the <Term id="content-addressable-store">content-addressable store</Term> into each project. Ten apps × React is still one copy of React’s files on disk.

```txt
store/.../react@19.2.8/index.js
  ↖ hard link
apps/web/node_modules/.pnpm/react@19.2.8/node_modules/react/index.js
  ↖ hard link
apps/admin/node_modules/.pnpm/react@19.2.8/node_modules/react/index.js
```

Editing a file inside `node_modules` would edit the store copy too — which is why you should never patch packages by hand. Use `pnpm patch` (or a proper fork) so the change is recorded.
