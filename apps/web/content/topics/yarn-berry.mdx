**Yarn Berry** is Yarn **2, 3, 4+**. New config (`.yarnrc.yml`), new constraints, and **<Term id="yarn-plug-n-play">Plug’n’Play</Term>** unless you opt out.

## Config that actually matters

**Plain English:** Config that actually matters — definition, example, and where you will see it.

```yml
# .yarnrc.yml
nodeLinker: node-modules   # optional: behave like Yarn 1 on disk
```

```json
{
  "packageManager": "yarn@4.9.1"
}
```

```bash
corepack enable
yarn install --immutable    # CI — fail if lockfile would change
yarn add lodash
yarn why react
yarn constraints            # optional: repo-wide dependency rules
```

<Term id="corepack">Corepack</Term> reads `packageManager` so everyone runs the same Yarn 4, not a leftover Yarn 1 from `brew`.

## What changed from Classic

**Plain English:** What changed from Classic — definition, example, and where you will see it.

| Classic (v1) | Berry (v2+) |
| --- | --- |
| `yarn.lock` (old format) | `yarn.lock` (new format — not interchangeable) |
| `.yarnrc` | `.yarnrc.yml` |
| `--frozen-lockfile` | `--immutable` |
| always `node_modules` | PnP by default |
| `yarn install` may mutate lockfile | CI should use `--immutable` |

Zero-installs (commit `.yarn/cache`) is optional. Most teams still gitignore the cache and let CI download, same as pnpm.

## Example: keep Berry, skip PnP

**Plain English:** Example: keep Berry, skip PnP — definition, example, and where you will see it.

```yml
# .yarnrc.yml
nodeLinker: node-modules
enableGlobalCache: true
```

You still get workspaces, `yarn workspace web add lodash`, and an immutable lockfile — without teaching every script about `.pnp.cjs`.
