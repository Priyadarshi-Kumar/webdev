An **MCP server** is a small process or HTTP service. The <Term id="mcp-host">host</Term> starts it (stdio) or POSTs to it (Streamable HTTP). The server answers structured requests. The **model stays in the host**.

## Read this in order

Short jargon note — read top to bottom:

1. **Register a tool** — Register a tool — explained with a short example.
2. **Two ways to run** — Two ways to run — explained with a short example.

## Register a tool

**Plain English:** Register a tool — definition, example, and where you will see it.

```ts
import { z } from "zod";

server.tool("search_docs", { query: z.string() }, async ({ query }) => ({
  content: [{ type: "text", text: await search(query) }],
}));
```

When the model wants docs, the host calls `tools/call` with `{ query: "lockfile" }`. Your `search` function runs. You return text. You never load an LLM SDK inside this process unless you *want* a second model (unusual).

Official TypeScript today often lives in `@modelcontextprotocol/server` (2026 spec). Older samples use `@modelcontextprotocol/sdk`.

## Two ways to run

**Plain English:** Two ways to run — definition, example, and where you will see it.

**stdio** — the host spawns `node dist/server.js`. Messages are newline-delimited JSON on stdin/stdout. Good for local files.

**HTTP** — the host POSTs to `https://mcp.example.com`. Good for shared company tools, auth headers, and not installing a CLI on every laptop.

```ts
// stdio (sketch)
const transport = new StdioServerTransport();
await server.connect(transport);
```

Keep servers small. One job (filesystem, GitHub, your tickets). A giant “do everything” server is harder to allowlist.
