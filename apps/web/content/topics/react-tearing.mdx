**Tearing** means part of the UI read store version A and another part read version B in the **same** render — or the server HTML does not match the first client render.

<Term id="concurrent-rendering">Concurrent rendering</Term> makes this more likely: React may pause a render. If you read `Date.now()` or `store.getState()` directly during render, a later component in the same pass can see a newer value.

## The naive read

**Plain English:** The naive read — definition, example, and where you will see it.

```tsx
// risky: window width during render differs on server (0) vs client
function Width() {
  return <span>{window.innerWidth}</span>;
}
```

On the server, `window` may not exist. On the client, it does. Even with a guard, two `Width` components could theoretically see two widths if a resize happens mid-render.

## The intended API

**Plain English:** The intended API — definition, example, and where you will see it.

```tsx
import { useSyncExternalStore } from "react";

function subscribe(onChange: () => void) {
  window.addEventListener("resize", onChange);
  return () => window.removeEventListener("resize", onChange);
}

export function Width() {
  const width = useSyncExternalStore(subscribe, () => window.innerWidth, () => 0);
  return <span>{width}</span>;
}
```

The third argument is the **server snapshot** (here `0`) so SSR has a defined value. React will <Term id="hydration">hydrate</Term> with `0`, then subscribe and update to the real width — one consistent snapshot per render.

## Zustand and friends

**Plain English:** Zustand and friends — definition, example, and where you will see it.

Libraries that support concurrent React use `useSyncExternalStore` internally. If you write `const n = myStore.count` during render, you are on your own. Use the library’s hook:

```tsx
const count = useStore((s) => s.count);
```
