A **Server Component** runs on the server (or at build time). It can `await` a database or file. It sends UI to the client. It **cannot** use `useState`, `useEffect`, or browser APIs.

## Fetch on the server

```tsx
// Server Component (no "use client")
export async function PostList() {
  const posts = await db.posts.findMany();
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```

The browser never sees the database call — only HTML (or a compact RSC payload). Secrets stay on the server.

## Where hooks live

A file with `"use client"` is a Client Component. That is where hooks live. Pass data down as props; do not fetch in `useEffect` if a Server Component can do it.

```tsx
"use client";

import { useState } from "react";

export function LikeButton({ postId }: { postId: string }) {
  const [liked, setLiked] = useState(false);
  return (
    <button onClick={() => setLiked(true)} disabled={liked}>
      {liked ? "Liked" : "Like"}
    </button>
  );
}
```

```tsx
// Server Component
import { LikeButton } from "./LikeButton";

export async function Post({ id }: { id: string }) {
  const post = await db.posts.find(id);
  return (
    <article>
      <h1>{post.title}</h1>
      <LikeButton postId={id} />
    </article>
  );
}
```

You can pass a Server Component as `children` into a client wrapper. You cannot import a Server Component **into** a client file and call it as a function — the client bundle cannot run `db`.
