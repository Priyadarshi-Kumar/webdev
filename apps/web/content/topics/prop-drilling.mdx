**Prop drilling** is threading a value through layers that only exist to forward it.

## Read this in order

Short jargon note — read top to bottom:

1. **The long way** — The long way — explained with a short example.
2. **Context skips the middle** — Context skips the middle — explained with a short example.
3. **When drilling is fine** — When this applies — and when to skip it.

## The long way

**Plain English:** The long way — definition, example, and where you will see it.

```tsx
function App() {
  const user = { name: "Priya" };
  return <Page user={user} />;
}
function Page({ user }: { user: { name: string } }) {
  return <Layout user={user} />;
}
function Layout({ user }: { user: { name: string } }) {
  return <Header user={user} />;
}
function Header({ user }: { user: { name: string } }) {
  return <p>{user.name}</p>;
}
```

`Page` and `Layout` do not care about `user`. Every new field (`avatar`, `role`) touches every file in the chain.

## Context skips the middle

**Plain English:** Context skips the middle — definition, example, and where you will see it.

```tsx
import { createContext, use } from "react";

type User = { name: string };
const UserContext = createContext<User | null>(null);

function App() {
  return (
    <UserContext value={{ name: "Priya" }}>
      <Page />
    </UserContext>
  );
}

function Header() {
  const user = use(UserContext);
  if (!user) return null;
  return <p>{user.name}</p>;
}
```

(`Provider` as `UserContext.Provider` is the older spelling; React 19 lets you use `<UserContext>`.)

## When drilling is fine

**Plain English:** When drilling is fine — definition, example, and where you will see it.

Do not put **everything** in context — it still re-renders consumers when the value identity changes. Drill one or two levels if that is clearer (`Button` receiving `onClick` is not a problem). Use context for **theme, auth, locale** — values many distant leaves need.

A store (Zustand) is another skip-the-middle option when updates are frequent and you want selectors.
