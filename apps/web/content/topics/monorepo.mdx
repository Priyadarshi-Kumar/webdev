A **monorepo** is one repository with more than one package — for example `apps/web` and `libs/utils`. You install **once at the root**. Apps depend on local libraries with <Term id="workspace-protocol">`workspace:*`</Term> instead of publishing to npm first.

## Shape of this site

**Plain English:** Shape of this site — definition, example, and where you will see it.

```txt
repo/
  package.json              # private: true, packageManager
  pnpm-workspace.yaml
  apps/web/package.json
  libs/utils/package.json
  libs/widgets/package.json
```

```yaml
# pnpm-workspace.yaml
packages:
  - "apps/*"
  - "libs/*"
```

npm and Yarn put the same globs in `"workspaces"` inside the root `package.json`. <Term id="nx">Nx</Term>, Turborepo, and pnpm filters all assume this shape.

## One install, many scripts

**Plain English:** One install, many scripts — definition, example, and where you will see it.

```bash
pnpm install                 # root only — links every workspace
pnpm --filter web dev        # run one package’s script
pnpm --filter @webdev/utils test
```

```json
{
  "name": "web",
  "dependencies": {
    "@webdev/widgets": "workspace:*",
    "react": "^19.2.8"
  }
}
```

Change a button in `libs/widgets` and the app sees it immediately — no `npm publish`. That is the point.

## Not a microfrontend

**Plain English:** Not a microfrontend — definition, example, and where you will see it.

A monorepo is a **git and install** choice. You can still ship **one** site from `apps/web`. A <Term id="microfrontend">microfrontend</Term> is a **deploy** choice: separate apps loaded at runtime. This repo is a monorepo, not a set of remotes.
