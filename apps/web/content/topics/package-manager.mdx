A **package manager** is the program that turns a shopping list (`package.json`) into files on disk (`node_modules`) plus a receipt (the lockfile).

JavaScript’s public warehouse is the <Term id="npm-registry">npm registry</Term>. **npm**, **Yarn**, and **pnpm** are three installers for that same warehouse — not three different stores.

## What it does

Without a package manager you would download zip files by hand, unzip them into a folder, and hope every nested library matches. The manager:

1. Reads <Term id="package-json">`package.json`</Term> (ranges like `^19.2.8`)
2. Resolves a full tree of nested packages
3. Writes a <Term id="lockfile">lockfile</Term> so the tree is repeatable
4. Puts files where Node can import them (`node_modules`, or Yarn PnP’s map)
5. Runs `scripts` you define (`dev`, `build`, `test`)

```bash
# install everything listed in package.json / the lockfile
npm install
yarn
pnpm install

# add one library to the shopping list and install it
npm install lodash
yarn add lodash
pnpm add lodash
```

## Everyday example

You start a Vite app and add React. The manager does more than copy `react/` — it also installs `scheduler`, `loose-envify`, and whatever else React lists.

```json
{
  "dependencies": {
    "react": "^19.2.8",
    "react-dom": "^19.2.8"
  }
}
```

```tsx
import { useState } from "react";

export function App() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}
```

`import "react"` works only after install. Commit the lockfile, not `node_modules`. Teammates and <Term id="ci">CI</Term> recreate the folder from that receipt.

## Pick one and stick to it

Mixing managers in one repo produces two lockfiles and two slightly different trees. This site uses **pnpm**. If you inherit a repo, use whichever lockfile is already there.

```bash
# see what you actually got
npm ls react
yarn why react
pnpm why react
```
